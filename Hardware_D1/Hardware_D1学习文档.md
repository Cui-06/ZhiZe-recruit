# Hardware_D1 学习文档

## 一、学习背景

`Hardware_D1` 题目要求使用 PWM 驱动直流编码电机，并通过三个按键完成速度和方向控制：

- 使用 PWM 驱动直流编码电机。
- 电机实现三级调速，速度大小由 Key1 控制，方向由 Key2、Key3 控制。
- Key1 第一次按下电机低速旋转，第二次中等速度旋转，第三次高速旋转，第四次按下电机停转。
- Key2 被按下，电机为正转模式；Key3 被按下，电机为反转模式。
- 串口上打印出当前位置和速度信息。

本项目使用 STM32F103C8T6 标准库工程完成。电机驱动采用 D153C / TB6612 模块的 A 通道，编码器电机使用 M310。STM32 负责输出 PWM、读取按键、读取编码器计数，并通过 USART1 周期性输出位置和速度信息。

## 二、工程结构

`Hardware_D1` 工程整体采用 `USER`、`HARDWARE`、`SYSTEM`、`CORE` 和标准库分层：

```text
Hardware_D1
├─ 工程源码
│  ├─ USER
│  │  ├─ main.c
│  │  ├─ Hardware_D1.uvprojx
│  │  ├─ Listings
│  │  └─ DebugConfig
│  ├─ HARDWARE
│  │  ├─ Board.c / Board.h
│  │  ├─ Key.c / Key.h
│  │  ├─ Motor.c / Motor.h
│  │  ├─ Encoder.c / Encoder.h
│  │  └─ Adc.c / Adc.h
│  ├─ SYSTEM
│  │  ├─ delay
│  │  ├─ sys
│  │  └─ usart
│  ├─ CORE
│  ├─ STM32F10x_FWLIB
│  └─ OBJ
├─ 实操记录
│  ├─ 01_编译日志.txt
│  ├─ 02_接线说明.md
│  ├─ 03_实物图.jpg
│  ├─ 04_演示视频.mp4
│  └─ 05_串口调试截图.png
└─ UartAssist.exe
```

主程序 `main.c` 负责系统初始化、按键事件处理、速度档位切换、方向切换和串口周期性上报。`HARDWARE` 目录负责各个硬件模块的底层封装，其中：

- `Board.c / Board.h`：统一管理 GPIO 引脚分配和初始化。
- `Key.c / Key.h`：读取 Key1、Key2、Key3，并完成消抖和按键锁定。
- `Motor.c / Motor.h`：配置 TIM3_CH4 硬件 PWM，控制 TB6612 的方向脚和占空比。
- `Encoder.c / Encoder.h`：使用 TIM4 编码器模式读取 M310 编码器增量。
- `Adc.c / Adc.h`：预留电机电源电压采样，当前主循环未把该值打印出来。
- `usart.c / usart.h`：初始化 USART1，并重定向 `printf` 到串口。

这种分层的好处是调试时可以逐个验证模块。例如先验证按键返回值，再验证 PWM 波形，再验证编码器计数，最后组合到主循环中。

## 三、学习过程

最开始先把题目拆成四个核心任务：电机驱动、按键控制、编码器测速和串口输出。电机驱动需要解决“速度”和“方向”两个维度；按键部分需要把一次按下转换成一次事件，不能因为长按导致速度档位连续跳变；编码器部分需要把一段时间内的计数增量转换成速度；串口部分用于观察系统当前状态，判断按键和电机反馈是否符合预期。

第一步是完成硬件引脚规划。PWM 选择 PB1，也就是 TIM3_CH4；TB6612 A 通道方向脚使用 PB14 和 PB15；编码器 A、B 相接到 PB6 和 PB7，对应 TIM4_CH1 和 TIM4_CH2；三个按键使用 PA2、PA3、PA4，并配置为内部上拉输入，按下时为低电平；USART1 使用 PA9 / PA10 输出调试信息。这样可以避免 PWM、编码器和普通 GPIO 之间互相占用。

第二步是配置电机 PWM。TIM3 的时钟经过 72 分频后得到 1 MHz 计数频率，自动重装载值设置为 999，因此 PWM 频率约为 1 kHz。低速、中速和高速三个档位分别使用 `CCR=200`、`CCR=400`、`CCR=700`，约等于 20%、40%、70% 占空比。停止时将占空比置 0，并同时拉低 AIN1 和 AIN2，避免驱动板保持某个有效输出状态。

第三步是处理方向控制。TB6612 A 通道的正转逻辑为 `STBY=1`、`AIN1=1`、`AIN2=0`、`PWMA=PWM`；反转时交换 AIN1 和 AIN2 的电平。程序中用 `Motor_SetDir()` 保存当前方向，然后调用 `Motor_ApplyOutput()` 把方向和当前速度同时作用到输出端。这样即使先按方向键再按速度键，最终电机也会按最后设置的方向运行。

第四步是完成按键逻辑。`Key_Read(0)` 每次返回一个按键事件。按键输入使用内部上拉，因此正常未按下时读到高电平，按下时读到低电平。检测到低电平后延时 10 ms 消抖，并用 `key_lock` 锁定本次按键，直到所有按键释放后才允许检测下一次按下。这样 Key1 的一次长按只会让速度档位变化一次。

第五步是配置编码器。STM32 的 TIM4 支持编码器接口模式，PB6 / PB7 分别接编码器两相信号。程序每隔 100 ms 调用一次 `Encoder_ReadA()`，读取 TIM4 的 16 位计数值后清零。主程序把每次读到的增量累加成当前位置，再用 `delta * 1000 / 100` 计算速度，单位为 `count/s`。

最后把各模块组合到 `main.c` 中。初始化完成后，主循环不断读取按键：Key1 控制速度档位从停止、低速、中速、高速循环；Key2 设置正转；Key3 设置反转。每 100 ms 通过串口输出一行：

```text
Motor A Pos=120 Speed=300 count/s
```

根据实操记录，工程已经通过 Keil 编译，结果为 `0 Error(s), 0 Warning(s)`，并生成了 `Hardware_D1.hex`。

## 四、实现功能总结

当前 `Hardware_D1` 已实现的主要功能如下：

- 上电后电机默认停止。
- Key1 第一次按下进入低速档，第二次进入中速档，第三次进入高速档，第四次停止，并循环执行。
- Key2 按下后设置电机正转模式。
- Key3 按下后设置电机反转模式。
- PWM 由 TIM3_CH4 硬件输出，频率约 1 kHz。
- 低速、中速、高速对应占空比约为 20%、40%、70%。
- 编码器由 TIM4 编码器模式读取，读取后清零，便于计算周期内增量。
- 主程序每 100 ms 累加一次编码器增量作为当前位置。
- 主程序每 100 ms 计算一次速度，单位为 `count/s`。
- USART1 以 115200 baud 输出当前位置和速度信息。
- 工程中预留了 ADC 电源电压采样模块，但当前串口输出内容只包含位置和速度。

当前主要引脚分配如下：

| 模块信号 | STM32 引脚 | 说明 |
| --- | --- | --- |
| Key1 | PA2 | 内部上拉，低电平按下 |
| Key2 | PA3 | 内部上拉，低电平按下 |
| Key3 | PA4 | 内部上拉，低电平按下 |
| TB6612 PWMA | PB1 / TIM3_CH4 | A 通道 PWM |
| TB6612 AIN1 | PB14 | A 通道方向脚 1 |
| TB6612 AIN2 | PB15 | A 通道方向脚 2 |
| M310 编码器 E1A | PB6 / TIM4_CH1 | 编码器 A 相 |
| M310 编码器 E1B | PB7 / TIM4_CH2 | 编码器 B 相 |
| 电源 ADC | PA6 / ADC1_CH6 | D153C 分压输出，当前主循环未打印 |
| USART1 TX | PA9 | 连接 USB-TTL RX |
| USART1 RX | PA10 | 连接 USB-TTL TX |

TB6612 A 通道和 M310 的核心接线为：

```text
PB1  -> PWMA
PB14 -> AIN1
PB15 -> AIN2
STBY -> D153C 3.3 V 或 5 V，保持高电平
AO1  -> M310 电机动力线 1
AO2  -> M310 电机动力线 2
PB6  -> M310 编码器 E1A
PB7  -> M310 编码器 E1B
```

串口接线为：

```text
USB-TTL TX  -> STM32 PA10 / USART1_RX
USB-TTL RX  -> STM32 PA9  / USART1_TX
USB-TTL GND -> STM32 GND
```

## 五、关键知识点总结

### 1. PWM 调速

PWM 调速的本质是用固定频率的脉冲控制电机获得的平均电压。占空比越大，电机获得的平均能量越多，转速通常越高。

本项目中 TIM3 的计数频率为：

```text
72 MHz / (71 + 1) = 1 MHz
```

自动重装载值 `ARR=999`，所以 PWM 周期为 1000 个计数，频率约为：

```text
1 MHz / 1000 = 1 kHz
```

速度档位和比较值对应关系如下：

| 速度状态 | 比较值 CCR | 近似占空比 |
| --- | ---: | ---: |
| 停止 | 0 | 0% |
| 低速 | 200 | 20% |
| 中速 | 400 | 40% |
| 高速 | 700 | 70% |

因为 `ARR=999`，理论满量程比较值接近 1000。程序中没有直接使用百分数，而是把不同档位映射为 TIM3 的比较值。

### 2. TB6612 H 桥方向控制

STM32 的 GPIO 不能直接驱动直流电机，原因是 GPIO 输出电流远小于电机启动电流，并且电机是感性负载，直接接 GPIO 容易损坏芯片。因此电机动力线必须接到 TB6612 的输出端，由驱动板承担电流输出。

TB6612 A 通道正转逻辑为：

```text
STBY = 1
AIN1 = 1
AIN2 = 0
PWMA = PWM
```

反转逻辑为：

```text
STBY = 1
AIN1 = 0
AIN2 = 1
PWMA = PWM
```

停止时程序将 `PWMA` 占空比置 0，并将 `AIN1`、`AIN2` 同时拉低。这样可以让停止状态更明确，避免电机在上电或切换状态时误转。

### 3. 按键消抖和事件锁定

机械按键按下和释放时会产生抖动。如果程序一检测到低电平就立即响应，可能一次按下被识别为多次按下。本项目在检测到按键按下后延时 10 ms，再次读取确认状态。

此外，程序中使用 `key_lock` 实现事件锁定：

- 所有按键释放时，`key_lock=1`，允许检测新事件。
- 检测到一次按下后，`key_lock=0`，本次长按期间不再重复触发。
- 等所有按键释放后，重新解锁。

这个处理对 Key1 很关键。如果没有锁定，一次长按可能在短时间内从低速跳到中速、高速甚至停止，无法稳定控制速度档位。

### 4. 速度档位状态机

Key1 的功能不是简单地“按下就加速”，而是四个状态循环：

```text
STOP -> LOW -> MID -> HIGH -> STOP
```

程序用 `speed++` 实现档位推进，当 `speed > MOTOR_SPEED_HIGH` 时回到 `MOTOR_SPEED_STOP`。这种写法比多个布尔变量更清晰，也便于后续增加档位或修改占空比。

方向控制和速度控制是分开的两个状态：

- `speed` 保存当前速度档位。
- `dir` 保存当前方向。

按 Key2 / Key3 只改变方向，不改变速度；按 Key1 只改变速度，不改变方向。这样用户操作更符合题目要求。

### 5. 编码器模式和位置统计

M310 编码器输出两路相位相差 90° 的脉冲信号。STM32 的 TIM4 可以工作在编码器接口模式下，根据 PB6 / PB7 两相信号自动判断计数方向并增减计数器。

本项目每 100 ms 读取一次 TIM4 计数：

```c
int16_t delta_a = Encoder_ReadA();
position_a += delta_a;
speed_a = delta_a * 1000 / 100;
```

其中：

- `delta_a` 是最近 100 ms 内的编码器增量。
- `position_a` 是从上电开始累计的位置。
- `speed_a` 是换算成每秒的计数值，单位为 `count/s`。

编码器计数的正负号由电机转向和 A/B 相接线顺序共同决定。如果发现正转时位置变小，可以交换编码器 A/B 相，或者在软件中对读数取反。

### 6. 滤波与抗干扰

这个项目里实际用到的“滤波”主要有两处：编码器输入滤波和电压采样平均滤波。

编码器部分在 `Encoder.c` 里把 `TIM_ICFilter` 设成了 6。TIM 的输入滤波会对脉冲信号做数字滤波，过滤掉短毛刺和抖动，避免编码器在高速或线缆干扰下产生错误计数。这个参数不能太小，否则抗干扰能力弱；也不能太大，否则真实脉冲也可能被滤掉，导致速度偏低。

电压采样部分在 `Adc_ReadAverage(8)` 中做了 8 次平均。单次 ADC 读数容易受电机启动、电源纹波和采样噪声影响，平均后数据会稳定很多。`Adc_ReadBatteryMillivolts()` 再把平均值换算成毫伏，适合后续做低电压保护或状态显示。

按键消抖本质上也是一种滤波，只不过过滤的是机械抖动而不是模拟噪声。这里使用 10 ms 延时和事件锁定，能避免一次按下被识别多次。

### 7. USART1 和 printf 重定向

工程使用 USART1 输出调试信息，串口参数为：

```text
115200 baud，8 数据位，1 停止位，无校验
```

`usart.c` 中重定义了 `fputc()`，使 `printf()` 的字符通过 USART1 发送。这样主程序可以直接写：

```c
printf("Motor A Pos=%ld Speed=%ld count/s\r\n", ...);
```

串口输出是本项目最重要的调试手段。即使肉眼能看到电机转动，也需要通过位置和速度数据确认编码器是否正常、方向是否符合预期、速度档位是否有效。

### 8. 供电和共地

电机启动电流通常明显大于空载稳定电流，不能从 STM32 的 3.3 V 引脚或 USB-TTL 的电源脚直接取电。本项目采用外部电源给 D153C 和电机供电，STM32 通过电脑 USB 供电。

需要注意：

- 电机动力电源接 D153C 的电机电源输入。
- STM32 不给电机直接供电。
- STM32、D153C、M310 编码器和 USB-TTL 需要有共同参考地。
- 不要把 D153C 的 5 V 输出、USB-TTL 的 5 V 和 STM32 USB 5 V 随意并联，避免电源互相反灌。
- STBY 必须接高电平，否则 TB6612 即使收到 PWM 和方向信号也不会输出。

### 9. ADC 电压采样预留

工程中包含 `Adc.c / Adc.h`，PA6 配置为 ADC1_CH6，用于读取 D153C 分压后的电源电压。函数 `Adc_ReadBatteryMillivolts()` 按 11:1 分压关系把 ADC 值换算成毫伏。

当前题目要求是串口打印位置和速度，因此主程序没有打印 ADC 电压。这个模块可以作为后续扩展，例如低电压报警、电机供电监控或串口状态输出补充。

## 六、踩坑记录

### 1. STBY 悬空导致电机不转

现象：PWM 和方向脚都已经连接，程序也能运行，串口正常输出，但电机没有动作。

原因：TB6612 的 STBY 是待机控制脚，必须保持高电平。STBY 悬空或为低电平时，驱动芯片处于待机状态，A 通道不会输出。

修正：将 STBY 接到 D153C 的 3.3 V 或 5 V，使驱动板保持使能状态。

经验：调 TB6612 时不要只检查 `PWMA`、`AIN1`、`AIN2`，还必须检查 `STBY`、电机电源和输出端 `AO1/AO2`。

### 2. TX/RX 没有交叉导致串口看不到输出

现象：程序下载正常，但串口助手没有显示 `Motor monitor ready` 或周期性位置速度信息。

原因：USART 通信需要交叉连接，USB-TTL 的 TX 要接 STM32 的 RX，USB-TTL 的 RX 要接 STM32 的 TX。如果 TX 接 TX、RX 接 RX，就无法通信。

修正：

```text
USB-TTL TX -> PA10 / USART1_RX
USB-TTL RX -> PA9  / USART1_TX
USB-TTL GND -> STM32 GND
```

经验：串口不通时先查波特率、TX/RX 交叉、GND、串口号和串口助手是否关闭 HEX 显示。当前工程波特率是 115200，不是 9600。

### 3. PWM 引脚复用配置错误

现象：方向脚变化正常，但电机速度不随 Key1 改变，甚至完全不转。

原因：PB1 是 TIM3_CH4，需要配置为复用推挽输出 `GPIO_Mode_AF_PP`。如果把 PB1 当成普通推挽输出，TIM3 的 PWM 信号不会正确输出到引脚。

修正：在 `Board_Init()` 中将 PB1 配置为 `GPIO_Mode_AF_PP`，并在 `Motor_Init()` 中初始化 TIM3_CH4。

经验：STM32 的定时器 PWM 需要同时满足两个条件：定时器通道配置正确，引脚也必须配置为对应的复用功能输出。

### 4. 供电接法不清导致电机动作异常

现象：电机启动时 STM32 复位、串口中断、或者电机只抖动不连续旋转。

原因：电机启动电流较大，如果直接从 STM32、USB-TTL 或电脑 USB 的弱电源侧取电，电压可能被拉低。另一方面，多路 5 V 电源随意并联也可能产生反灌风险。

修正：外部电源只给 D153C 和电机供电，STM32 由电脑 USB 供电；控制信号之间保持共同 GND；不要把多个 5 V 输出端直接并到一起。

经验：电机类项目调试时，供电问题和程序问题很容易表现得相似。判断时应同时观察串口是否重启、电源电压是否跌落、驱动板指示灯是否异常。

## 七、收获

通过 `Hardware_D1`，我对 STM32 驱动编码电机的完整链路有了更清晰的理解。PWM 只解决“给多少功率”的问题，H 桥方向脚解决“往哪个方向转”的问题，编码器解决“实际转了多少”的问题，串口则用于把内部状态暴露出来，帮助判断系统是否真的按预期运行。

这次任务中最重要的收获是把电机控制拆成可验证的模块。先让 PWM 有输出，再让 TB6612 能按方向驱动电机，再让编码器有计数，最后用串口把位置和速度打印出来。每个阶段都可以单独验证，问题定位会比直接把所有代码写完后一起调试更可靠。

另外，对硬件题来说，代码正确只是必要条件，不是充分条件。STBY、共地、外部电源、TX/RX 交叉、按键上拉、PWM 复用模式、编码器 A/B 相序都会直接影响最终现象。后续做类似题目时，应先完成引脚表和接线表，再写驱动代码；调试时每次只改变一个变量，用串口输出和实物现象共同确认结果。
