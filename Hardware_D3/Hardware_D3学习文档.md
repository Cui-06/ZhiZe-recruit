# Hardware_D3 学习文档

## 一、学习背景

`Hardware_D3` 的题目要求延续了 D2 的基础，但控制目标更进一步：不只是让电机能按目标位置运动，而是要让它更稳、更快、更少过冲。

题目要求包含：

- 使用 IIC 协议的 0.96 英寸 OLED 显示当前速度和位置信息。
- 设计位置-速度串级 PID，使电机按照目标速度到达目标位置。
- 在串级 PID 基础上加入速度前馈、条件积分抗饱和和速度滤波，展示控制质量改善。
- 通过电位器或旋钮设定目标位置，按钮控制目标速度。
- 使用串口画图工具展示 PID 效果。

在 D3 中，控制策略已经改成改进型位置-速度串级控制：

- 位置环由单纯 P 改为带速度反馈阻尼的 PD。
- 速度环改为“速度前馈 + PI”。
- 增加条件积分抗饱和。
- 编码器速度增加 4 点滑动平均。

这套结构的核心变化是：位置环不再直接粗暴地给 PWM，而是先生成目标速度；速度环再根据目标速度输出最终 PWM。这样系统的动态更柔和，目标附近更容易停稳。

## 三、学习过程

我这次的思路是先把 D2 的单环位置控制拆开，再把它改成串级结构。

第一步先确认输入链路。PA0 上的电位器用于设定目标位置，程序把 ADC 值线性映射成 `-5000 ~ +5000 count` 的位置范围。PA2 按钮用于切换目标速度档位，依次是停止、低速、中速、高速，对应速度上限 `0 / 2000 / 4000 / 7000 count/s`。

第二步确认反馈链路。TIM4 以编码器模式读取 M310 的 A/B 相脉冲，每 10 ms 读一次并立即清零。这样读到的就是一个采样周期内的增量，既能累加成当前位置，也能换算成速度。

第三步改控制策略。D2 里位置 PID 直接输出带符号 PWM，D3 则改成“位置 PD + 速度 PI + 前馈”。也就是说，远离目标时，位置环会给出较大的目标速度；接近目标时，速度反馈会提前介入，给系统加阻尼，减少过冲和来回摆动。

第四步补稳速度环。速度环不是单纯 PI，而是加了速度前馈。前馈负责快速提供基础 PWM，PI 只修正负载和模型误差。这样调起来比单纯靠 PI 快，输出也更干净。

第五步处理抗饱和和滤波。速度环加入条件积分，PWM 已经饱和时不再继续向同方向积分；换向或停车时清除旧方向积分。编码器速度还加了 4 点滑动平均，目的是压掉量化抖动，让曲线更平滑。

最后把 OLED 和 SerialPlot 接上。OLED 显示当前速度、当前位置、目标速度和目标位置；串口输出 6 列 CSV 数据，方便观察串级控制的跟随过程和到位质量。

## 四、实现功能总结

当前 `Hardware_D3` 已实现的主要功能如下：

- 上电后初始化 OLED，并显示速度、位置、目标速度、目标位置。
- 使用 0.96 英寸 IIC OLED 实时显示状态。
- 使用 PA0 电位器设定目标位置。
- 使用 PA2 按钮切换目标速度档位。
- 使用改进型位置-速度串级控制。
- 位置环采用带速度反馈阻尼的 PD。
- 速度环采用“前馈 + PI”。
- 速度反馈使用 4 点滑动平均。
- 速度环加入条件积分抗饱和。
- 串口以 115200 baud 输出 6 列 CSV 数据供 SerialPlot 画图。
- 控制周期为 10 ms，串口输出周期为 20 ms，OLED 刷新周期约为 100 ms。

当前主要引脚分配如下：

## 五、关键知识点总结

### 1. 串级控制的结构

D3 的核心不是“一个 PID 管到底”，而是外环管位置、内环管速度。

外环位置 PD 的作用是把位置误差转换成目标速度：

```text
target_speed = Kp * position_error - Kd * current_speed
```

这里直接把实际速度作为阻尼项，相当于在接近目标时主动刹车。这样比单纯位置 P 更不容易冲过头。

内环速度 PI 的作用是让电机真正跟上目标速度：

```text
pwm = feedforward + Kp * speed_error + Ki * integral
```

前馈负责“先给一口气”，PI 负责修正“差多少补多少”。这个结构比单独靠 PI 更快，更适合电机这类惯性明显的对象。

### 2. 位置环 PD

位置环不再输出 PWM，而是输出目标速度。它的优势有两个：

- 位置误差大时，系统能快速拉开速度。
- 接近目标时，速度反馈会提前减速，降低超调。

也就是说，位置环的任务不是让电机一直跑，而是让电机朝目标位置走，并且在接近目标时自然变慢。

代码里还加了位置死区，误差很小时直接让目标速度为 0，这样最终停得更稳，不会在目标点附近来回找平衡。

### 3. 速度环前馈 + PI

速度环使用前馈加 PI 的原因很实际：电机不是理想线性对象，单靠 PI 往往会在负载变化时表现出迟滞。

前馈项先按照目标速度给一个基础 PWM，让电机先动起来；PI 只负责补偿误差和负载扰动。这样做的结果是：

- 响应更快。
- 速度上升更直接。
- PI 不需要承担全部驱动力，积分压力更小。

### 4. 条件积分抗饱和

速度环里最容易出问题的是积分饱和。PWM 已经顶到上限时，如果还继续积累同方向误差，等系统回到可控区后，积分会把电机“推过头”。

所以 D3 加了条件积分：

- PWM 饱和且误差还在推动同方向时，不继续积分。
- 换向时清空旧方向积分。
- 停车时清空积分。

这几个处理能明显减少：

- 起步猛冲。
- 换向拖尾。
- 停止后再次启动的冲击。

### 5. 编码器速度 4 点滑动平均

编码器每 10 ms 读一次，原始速度是离散的，抖动会比较明显。D3 把最近 4 次速度做滑动平均：

```text
v_avg = (v0 + v1 + v2 + v3) / 4
```

这个滤波不会改变位置累计值，只是让速度曲线更平滑。它的意义不是“变快”，而是“更像真实速度”。

### 6. 按键和目标速度档位

按键接口沿用 D1 的 `Key_Read(mode)`、`KEY1_PRESS` 和 `KEY_UNPRESS` 命名。函数每 10 ms 调用一次，通过稳定采样和按键锁定产生一次按下事件。按钮负责切换目标速度上限，不直接改位置目标。

速度档位循环为：

```text
0 -> 2000 -> 4000 -> 7000 -> 0
```

这意味着位置环输出的目标速度会被按钮档位限制住。远离目标时可以跑得快，接近目标时也不会无限冲。

### 7. OLED 和串口画图

OLED 显示的是低频状态信息，适合人眼看：

- `SPD`：实际速度
- `POS`：当前位置
- `TSPD`：目标速度
- `TPOS`：目标位置

串口画图工具则用来观察动态过程。主程序以 50 Hz 输出 6 列 CSV，能直接看到：

- 目标位置变化后实际位置是否跟随。
- 目标速度是否被按钮档位限制。
- PWM 是否经常饱和。
- 误差是否快速收敛。

这比只看 OLED 更容易判断串级控制是否真的有效。

### 8. 控制周期和任务分工

TIM2 以 100 Hz 运行控制逻辑，也就是 10 ms 一次。这个中断里只做控制所必需的短运算：

- 读编码器。
- 读电位器。
- 扫按钮。
- 算串级 PID。

OLED 刷新和串口输出放在主循环里低频执行。这样做的原因是：闭环控制最怕控制周期被拖慢。只要把耗时操作挪出中断，系统会稳定很多。

### 9. PWM 和方向控制

电机驱动仍然依赖 TB6612。TIM3_CH4 从 PB1 输出 PWM，AIN1/AIN2 决定方向。

`Motor_SetDuty()` 里，PWM 输出的正负号直接对应电机方向：

- 正值：正转。
- 负值：反转。
- 0：停车。

这和串级控制的输出逻辑是匹配的：位置误差决定朝哪个方向追，速度环决定以多大力度追。

### 10. 供电与共地

电机类项目最容易出问题的还是供电。电机启动电流大，供电不稳时会把整个系统拉低，表现成复位、OLED 乱闪、串口中断或者电机抖动。

本项目里仍然需要注意：

- 电机动力电源和 STM32 逻辑电源分开。
- 所有信号模块必须共地。
- OLED 和编码器信号必须共享 STM32 的参考地。
- TB6612 的 STBY 必须为高电平。

## 六、踩坑记录

### 1. OLED 接线错误

现象：OLED 能上电，但屏幕不显示。

原因：SCL/SDA 接线错误，没有正确接到 PB10/PB11，导致 OLED 虽然上电，但 IIC 初始化没有真正成功。

修正：重新核对 `OLED SCL -> PB10`、`OLED SDA -> PB11`，并把 OLED 的 VCC 和 GND 接稳。

经验：OLED 不显示时先查接线，尤其是 SCL/SDA 是否接反或接错。

### 2. PID 参数过大导致振荡

现象：目标附近来回摆动，位置很难真正停稳。

原因：位置环或速度环的增益过大时，系统对误差反应过猛，尤其在编码器反馈有抖动时更明显。

修正：先把速度上限降下来，再逐步调位置环和速度环参数。通常先调位置环，再调速度环，最后再看前馈大小。

经验：串级控制不是参数越大越好，能稳定收敛比响应过快更重要。

### 3. 积分残留导致再次启动冲击

现象：电机停止后再启动，输出突然很大，出现明显冲击。

原因：旧方向的积分没有清零，重新启动时会把历史误差一并释放出来。

修正：在停车、换向和输出饱和时使用条件积分策略，必要时直接清零积分状态。

经验：闭环系统里“停住”不只是把 PWM 变成 0，还要把历史状态处理干净。

### 4. 串口画图看起来“没效果”

现象：串口助手能看到数据，但 SerialPlot 曲线不对，或者没有正常更新。

原因：格式错误。输出里如果混入文字、列数不对、少了换行，或者波特率不一致，SerialPlot 都可能无法正确识别。

修正：保持输出纯数字 CSV，例如：

```text
5000,4870,3200,3100,260,120
```

并确认波特率是 115200，数据位 8，停止位 1，无校验。

经验：画图工具对格式很敏感，调试时先保证输出纯净，再看曲线。

### 5. 控制周期被阻塞

现象：OLED 刷新或串口输出过密时，控制响应变慢。

原因：如果把耗时操作放进控制中断，10 ms 周期会被拉长，位置 PD 和速度 PI 的采样时刻不稳定，闭环效果会明显变差。

修正：控制逻辑尽量放在中断里做短运算，OLED 和串口放到主循环里低频处理。

经验：闭环系统最忌讳“边控制边刷屏”。实时性比界面更重要。

### 6. 速度滤波过强会拖慢响应

现象：速度曲线很平滑，但电机反应看起来慢了一拍。

原因：速度做了 4 点滑动平均后，抖动变少，但同时也引入了一点延迟。

修正：保持 4 点平均不再继续加大；如果后续要更快响应，就要重新权衡滤波长度和控制周期。

经验：滤波不是越强越好，滤波和响应速度必须平衡。

## 七、收获

这次 D3 的收获，比 D2 更集中地体现在“控制结构”上。

D2 主要解决的是位置闭环能不能跑起来，D3 解决的是同一套硬件下能不能跑得更稳。串级控制把“位置”和“速度”拆开后，问题就清楚了：位置环负责方向和大趋势，速度环负责执行和修正，前馈负责加速，条件积分负责收尾。

我对改进型位置-速度串级控制的理解更具体了：

- 位置环不是直接控制 PWM，而是控制目标速度。
- 速度环才是最终的执行层。
- 速度反馈阻尼能减少过冲。
- 前馈能提高响应速度。
- 条件积分能避免饱和后失控。

这次实验也让我更重视“看曲线”这件事。OLED 适合看状态，SerialPlot 适合看动态过程，编码器适合看反馈，电位器适合调目标，按钮适合切速度上限。把这些工具分开用，调试效率会高很多。

最后，闭环项目最有效的做法还是先搭完整链路，再逐步验证。先确认接线和供电，再确认反馈和驱动，再确认控制周期和数据输出，最后再调参数。这样更容易定位问题，也更容易看出改进型串级控制到底有没有真的起作用。
