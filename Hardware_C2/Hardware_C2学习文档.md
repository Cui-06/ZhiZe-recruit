# Hardware_C2 学习文档

## 一、学习背景

`Hardware_C2` 是在 `Hardware_C1` 的基础上继续扩展的综合实验。C1 已经完成了独立按键、电机 PWM、蜂鸣器、LED 和数码管等模块的整合，C2 的重点是加入 IIC 协议的 0.96 英寸 OLED，并在电机高速旋转时实现“急救请避让”的从右向左滚动显示。

本次题目要求为：

- 使用 IIC 协议的 0.96 英寸屏幕，在电机高速旋转的时候滚动显示“急救请避让”的字样。
- 不能使用闪烁的方法显示，必须是滚动显示。
- 字样从右向左滚动。

## 二、工程结构

`Hardware_C2` 仍然采用 `User` 和 `Driver` 分层：

```text
Hardware_C2
├─ User
│  ├─ main.c
│  ├─ Listings
│  └─ Objects
└─ Driver
   ├─ Key.c / Key.h
   ├─ Motor.c / Motor.h
   ├─ Beep.c / Beep.h
   ├─ Led.c / Led.h
   ├─ Seg.c / Seg.h
   └─ OLED.c / OLED.h
```

主程序 `main.c` 负责整体流程控制，OLED、蜂鸣器、电机、按键等底层操作放在 `Driver` 中。这样可以避免主程序里堆太多 IO 细节，后续调试 OLED 时也能集中修改 `OLED.c`。

## 三、学习过程

最开始是把 C1 的基础功能迁移到 C2，包括电机三档调速、蜂鸣器高速报警、LED 和数码管初始化熄灭等。之后加入 OLED 底层，使用软件 IIC 方式控制屏幕。

OLED 加入后，首先遇到的问题是上电完全不亮。这个问题排查了比较久，因为程序可以编译，但实物没有任何显示。后来通过加入最小亮屏测试、检查工程文件是否加入、检查 IIC 地址、检查接线和引脚，最终发现问题主要出在最初选择的 `P3.6/P3.7` 不适合软件 IIC。换到 `P1.2/P1.3` 后，OLED 才正常点亮。

OLED 点亮后，又继续处理最终效果问题。调试阶段加入过开机全屏自检，但题目要求初始状态不应该显示内容，所以后续删除了开屏自检，改成初始化后清屏并关闭显示，只有电机高速时才打开 OLED 并滚动显示文字。

滚动显示部分也经历了多次修正。最初文字进入屏幕太慢，看起来像高速档开启后几秒才显示；后来发现是文字初始位置设得太靠右。接着又出现第一个字直接出现在中间、上下半字不同步、字形时宽时窄等问题。最终通过“文字左边界”建模、连续 IIC 传输、垂直寻址、按列发送上下半字等方式，完成了稳定的从右向左滚动。

## 四、实现功能总结

当前 `Hardware_C2` 实现的主要功能如下：

- 初始状态下电机停止。
- 初始状态下蜂鸣器关闭。
- 初始状态下 LED、数码管和 OLED 熄灭。
- `KEY1` 控制电机速度循环切换：停止、低速、中速、高速。
- `KEY2` 设置电机正转。
- `KEY3` 设置电机反转。
- 电机高速时，蜂鸣器发出双频“滴露滴露”提示音。
- 电机高速时，OLED 从右向左滚动显示“急救请避让”。
- 退出高速档后，蜂鸣器关闭，OLED 关闭显示。

当前主要引脚分配为：

| 模块 | 引脚 |
| --- | --- |
| 电机驱动 `AIN1` | `P1.0` |
| 电机驱动 `AIN2` | `P1.1` |
| OLED `SCL` | `P1.2` |
| OLED `SDA` | `P1.3` |
| 蜂鸣器 | `P2.5` |
| LED | `P2.0` |
| 数码管段选 | `P0` |
| 数码管位选 | `P2.2~P2.4` |
| 独立按键 | `P3.0~P3.3` |

## 五、关键知识点总结

### 1. 软件 IIC

OLED 使用软件 IIC 通信，主要依靠 `SCL` 和 `SDA` 两根线模拟 IIC 起始、停止和字节发送时序。

```c
sbit OLED_SCL = P1^2;
sbit OLED_SDA = P1^3;
```

软件 IIC 对引脚电平和时序比较敏感，因此应优先选择普通空闲 IO。像 `P3.6/P3.7` 这类带有 `/WR`、`/RD` 复用功能的引脚，在开发板上可能受到外围电路影响，不适合作为本次 OLED 的 IIC 引脚。

### 2. OLED 初始化

OLED 初始化需要先发送一组控制命令，设置寻址方式、扫描方向、对比度、电荷泵等参数。初始化完成后，C2 中执行一次全屏清屏，然后关闭显示：

```c
OLED_Clear();
OLED_DisplayOff();
```

这样可以保证 OLED 显存初始状态干净，同时上电后屏幕不亮，符合初始状态要求。

### 3. 显示开启和关闭

C2 中不在开机时显示内容，而是通过开关状态控制 OLED：

```c
OLED_SetScrollEnable(speed == MOTOR_SPEED_HIGH);
```

当电机进入高速档时，OLED 打开并刷新滚动文字；退出高速档时，OLED 直接发送 `Display OFF` 命令关闭显示。关闭显示比反复全屏清屏更快，也不会在档位切换时造成明显阻塞。

### 4. 文字滚动建模

最终采用“文字左边界”的方式描述滚动位置：

```c
#define OLED_TEXT_START_LEFT (OLED_WIDTH - 1)
static int OLED_TextLeft = OLED_TEXT_START_LEFT;
```

刷新屏幕每一列时，用屏幕列坐标减去文字左边界，得到当前应该显示的字模列：

```c
text_col = (int)x - OLED_TextLeft;
```

这样第一帧只会从屏幕最右侧进入一列，之后逐列向左移动，不会出现文字突然从中间冒出的问题。

### 5. 16×16 汉字显示

“急救请避让”使用 16×16 点阵汉字。一个汉字高度为 16 点，对应 OLED 的上下两个显示页。若先写完整个上半页，再写下半页，传输较慢时可能出现上下半字不同步。

最终改为垂直寻址并按列发送：

```c
OLED_IIC_WriteByte(upper);
OLED_IIC_WriteByte(lower);
```

每一列先写上 8 点，再紧接着写下 8 点，可以让上下半字保持同一帧。

### 6. 连续 IIC 传输

最开始每写一个显示数据字节都重新发送起始信号、地址、控制字和停止信号，开销很大。后来改为同一区域连续发送数据，只建立一次 IIC 数据流：

```c
OLED_DataStreamStart();
...
OLED_DataStreamEnd();
```

这样能明显减少 OLED 刷新时间，也能降低滚动延迟。

### 7. 滚动速度

提高滚动速度不能只靠增大每帧移动步长。步长过大时，文字会跳动，甚至出现字形时宽时窄。C2 最终选择每帧移动 1 列，同时减少软件 IIC 延时，提高传输速度，使滚动更连续。

## 六、踩坑记录

### 1. OLED 上电完全不亮

现象：加入 OLED 后程序能编译，但上电完全黑屏。

原因：最初使用 `P3.6/P3.7` 作为 `SCL/SDA`，这两个引脚在 8051 上复用为 `/WR` 和 `/RD`，在开发板上可能受到外围电路影响，导致软件 IIC 不能稳定通信。

修正：将 OLED 引脚改为：

```c
sbit OLED_SCL = P1^2;
sbit OLED_SDA = P1^3;
```

经验：OLED 黑屏时，先做最小亮屏测试，再排查地址、接线、电源和引脚。软件 IIC 尽量选择普通空闲 IO。

### 2. 开屏自检残留

现象：OLED 点亮后，开机仍然会亮一下，不符合最终题目要求。

原因：前期为了排查黑屏加入过全屏点亮自检，后续忘记删除。

修正：删除开屏自检，初始化后清屏并关闭显示。高速档开启时再打开 OLED。

经验：调试代码解决问题后要及时清理，否则会影响最终演示效果。

### 3. 高速档开启后几秒才显示

现象：进入高速档后，OLED 不是立刻出现文字，而是等待几秒后才看到内容。

原因：滚动初始位置过于靠右，文字实际已经开始滚动，但还没有进入屏幕范围。同时，切换时全屏清屏和低效 IIC 传输也会造成阻塞。

修正：用 `OLED_TEXT_START_LEFT (OLED_WIDTH - 1)` 作为起点，并取消高速档切换时的全屏清屏。

经验：滚动延迟不一定是没有触发，也可能是坐标起点和刷新耗时共同造成的。

### 4. 第一个字直接出现在屏幕中

现象：为了减少等待时间，调整初始偏移后，第一个字不是从右边缘进入，而是直接出现在屏幕中。

原因：起点设置成了 `OLED_WIDTH - OLED_FONT_WIDTH` 一类的位置，第一个 16 点宽汉字一开始就完整落在屏幕内。

修正：使用文字左边界建模，起点为 `OLED_WIDTH - 1`，让文字从最右侧逐列进入。

经验：滚动显示要明确“起点代表文字哪一部分的位置”，不能只凭感觉调偏移值。

### 5. 全屏清屏和逐字节 IIC 导致延迟

现象：高速档开启后第一帧刷新不及时，屏幕会保持空白一段时间。

原因：软件 IIC 全屏清屏需要写 8 页、共 1024 字节；如果每个字节还单独建立一次 IIC 事务，时间会更长。

修正：初始化时保留一次全屏清屏，档位切换时不再全屏清屏；显示数据改为连续 IIC 传输。

经验：档位切换路径中应避免耗时阻塞操作。

### 6. 上下半字不同步

现象：文字滚动时，汉字上半部分和下半部分移动不同步。

原因：16×16 汉字跨两个 OLED 页，如果先写完整个上半页再写下半页，OLED 扫描过程中可能显示到两帧混合的结果。

修正：改用垂直寻址，按列连续发送上半字节和下半字节。

经验：跨页显示 16×16 汉字时，按列刷新比按页分开刷新更稳定。

### 7. 字形时宽时窄

现象：加快滚动后，字形看起来有时变宽、有时变窄。

原因：每帧移动步长过大，同时 IIC 传输速度不够快，OLED 扫描时容易显示到新旧帧交界。

修正：将滚动步长恢复为每帧 1 列，并缩短软件 IIC 延时。

经验：提高滚动速度应优先优化传输效率，不宜单纯增加每帧位移。

## 七、收获

通过 `Hardware_C2`，我对 51 单片机的软件 IIC、OLED 初始化、点阵字模显示和滚动刷新有了更完整的理解。相比 C1，C2 的难点不只是让模块工作，而是让显示效果符合题目要求，包括初始不亮、只在高速档显示、必须滚动、从右向左进入、滚动不能撕裂等细节。

这次最大的收获是排查问题时要分层判断：黑屏时先判断接线和底层通信，能亮后再判断显示内容，能显示后再优化滚动坐标和刷新速度。很多 OLED 问题表面看起来都是“不显示”，但背后的原因可能分别是引脚选择、初始化命令、全屏清屏阻塞、滚动起点、IIC 传输方式或跨页刷新不同步。
