# Rational 有理数类学习文档

## 一、题目理解

本题要求使用 C++ 设计一个 `Rational` 有理数类。一个有理数可以表示为：

\[
\frac{numerator}{denominator}
\]

其中分母不能为 0。类需要支持以下功能：

- 自动约分，并把分母统一为正数；
- 加、减、乘、除四则运算；
- 以最简形式输出结果；
- 通过封装保护分子和分母；
- 通过构造函数重载支持不同形式的对象创建；
- 对零分母和除零等非法操作进行安全处理。

## 二、学习过程

### 1. 了解 C++ 类的基本结构

参考 W3Schools 的 C++ OOP 教程后，我先区分了类的三个重要组成部分：

- `private`：保存对象内部数据，只允许类的成员函数访问；
- `public`：提供给外部调用的构造函数和运算接口；
- 成员函数：描述对象可以执行的操作。

因此，`Rational` 类把分子 `numerator_` 和分母 `denominator_` 设为私有成员，外部不能直接修改它们，只能通过构造函数和运算符操作有理数。

### 2. 设计对象的有效状态

有理数的规范状态约定为：

1. 分母始终不为 0；
2. 分母始终为正数，负号统一放在分子上；
3. 分子和分母始终已经约分到最简形式；
4. 0 统一表示为 `0/1`，输出时显示为 `0`。

所有构造函数最后都会调用 `normalize()`，这样对象一旦创建，就处于有效且统一的状态。

### 3. 实现最大公约数和约分

约分使用欧几里得算法求最大公约数：不断用余数替换较大的数，直到余数为 0。设最大公约数为 `gcd`，则：

```text
numerator   /= gcd
denominator /= gcd
```

例如 `-6/-8` 会先统一符号为 `6/8`，再约分为 `3/4`；`6/-8` 会变为 `-3/4`。

### 4. 重载四则运算符

为了让表达式更接近数学写法，类重载了 `+`、`-`、`*` 和 `/`：

```cpp
Rational result = first + second;
```

具体计算规则如下：

| 运算 | 计算公式 |
| --- | --- |
| 加法 | `a/b + c/d = (a*d + c*b)/(b*d)` |
| 减法 | `a/b - c/d = (a*d - c*b)/(b*d)` |
| 乘法 | `a/b * c/d = (a*c)/(b*d)` |
| 除法 | `a/b / c/d = (a*d)/(b*c)`，且 `c` 不能为 0 |

每个运算符都返回新的 `Rational` 对象。新对象的构造过程会再次调用 `normalize()`，所以运算结果会自动约分和规范化。

### 5. 实现规范化输出

重载输出运算符后，可以直接使用：

```cpp
std::cout << value;
```

当分母为 1 时只输出整数，例如 `5/1` 输出为 `5`；其他情况输出为 `分子/分母`，例如 `2/3` 输出为 `2/3`。

## 三、关键知识点总结

### 1. 封装

`numerator_` 和 `denominator_` 是 `private` 成员，外部无法直接赋值。这避免了出现分母为 0、分数未约分等无效状态，体现了“数据和操作绑定在类内部”的封装思想。

### 2. 构造函数重载

类提供了三种构造方式：

```cpp
Rational a;             // 0/1
Rational b(5);          // 5/1
Rational c(6, 8);       // 3/4
```

参数数量不同的构造函数可以满足默认值、整数和分数等不同使用场景。

### 3. `const` 成员函数和常量引用

四则运算函数声明为 `const`，表示运算不会修改左操作数。参数使用 `const Rational&`，避免不必要的对象复制，同时保证不会修改右操作数。

### 4. 运算符重载

运算符重载让自定义类型可以使用自然的数学表达式。重载函数仍然遵守原有运算符的含义，并通过返回新对象避免破坏参与运算的原对象。

### 5. 异常处理

- 构造有理数时，分母为 0，抛出 `std::invalid_argument`；
- 除法中除数为 0，抛出异常，调用方可以通过 `try-catch` 处理；
- `main` 中捕获 `std::exception`，统一输出错误信息并结束程序。

## 四、踩坑记录

### 1. 负分母导致输出不规范

如果直接保存 `1/-2`，输出会出现 `1/-2`。虽然数值上正确，但通常约定负号写在分子上。因此在约分前检查分母，若分母小于 0，就同时改变分子和分母的符号。

### 2. 不能只在输出时约分

如果只在 `operator<<` 中约分，后续运算仍然使用未约分的数据，代码复杂且容易遗漏。更好的做法是在构造函数中统一调用 `normalize()`，让每个对象从创建开始就保持规范状态。

### 3. 忘记检查除数为零

除法的分母来自右操作数的分子，因此不能只检查右操作数的分母。正确的检查条件是 `other.numerator_ == 0`。

### 4. 零的最大公约数处理

例如 `0/5` 的最大公约数是 5，约分后得到 `0/1`。欧几里得算法需要正确处理第一个参数为 0 的情况，不能简单假设两个参数都为正数。

### 5. 整数溢出风险

当前实现使用 `long long` 保存分子和分母。多个大数相乘或通分时，临时结果可能超出 `long long` 的范围。实际工程中可以进一步使用溢出检查、`__int128` 中间变量或大整数库。本题数据规模较小时，`long long` 已能满足练习要求。

### 6. 源文件编码

源代码中的中文注释需要使用 UTF-8 保存，并在 Visual Studio 工程中指定 `/utf-8`，否则可能出现注释乱码。字符串错误信息也应尽量使用稳定的编码，便于跨编译器运行。

## 五、测试思路与示例

可以使用以下输入检查主要功能：

```text
第一组：6 8
第二组：1 6
```

构造后两个数分别为 `3/4` 和 `1/6`，预期结果为：

```text
3/4 + 1/6 = 11/12
3/4 - 1/6 = 7/12
3/4 * 1/6 = 1/8
3/4 / 1/6 = 9/2
```

## 六、总结

本题将面向对象中的封装、构造函数重载、成员函数、运算符重载和异常处理结合起来。实现的核心不是简单保存两个整数，而是通过 `normalize()` 保证对象始终满足统一的不变量。这样，四则运算只需要按照数学公式生成新对象，约分和符号处理由类内部自动完成，既简化了调用代码，也提高了数据安全性和可维护性。
